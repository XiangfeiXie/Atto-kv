# kvstore 内存基准：纯插入下的占用与回收

脚本 [`test/bench/bench_pool_mem.sh`](test/bench/bench_pool_mem.sh)，原始数据 [`test/bench/results_pool_mem.txt`](test/bench/results_pool_mem.txt)。

四形态 = 2 个二进制（jemalloc / glibc）× 2 条配置（运行期 `kv_pool off|on`）。三档 value（key 固定 16B，故 entry 整块 = 48 + V），按"池相对底座是否省内存"选取：

| 档 | V | entry 整块 | 池档位 | jemalloc | glibc chunk | N |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 不省档 | 16 | 64 | 64 | 64 | 80 | 1,000,000 |
| 省档 | 240 | 288 | 288 | 320 | 304 | 400,000 |
| 亏损档 | 465 | 513 | 576 | 640 | 528 | 200,000 |

三列数据同取进程自报的 `[MEM]` 行：启动 `[MEM] startup`、峰值 `[MEM] shutdown/pre-release`、回收 `[MEM] shutdown/post-release`（FLUSHALL 全清归还后）。
**对比 glibc 无池节省率** = `(1 − 该形态峰值/key ÷ glibc 峰值/key) × 100%`，正值表示比 glibc 无池少占。

## 池的净影响（Δ = 有池 − 无池，同底座内相减）

| 档 | jemalloc 底座 | glibc 底座 |
| --- | ---: | ---: |
| V=16（不省档） | +0.1 B/key | −15.9 B/key |
| V=240（省档） | −31.2 B/key | −15.1 B/key |
| V=465（亏损档） | −60.1 B/key | **+52.2 B/key** |

## 简要说明

- **启动**：池使启动内存增加约 20KB（227,808 → 248,288），有界且不随数据量增长。glibc 形态启动值（6–7KB）远低于 jemalloc（228–248KB），是两个底座 arena 的固有开销差异，与池无关。
- **峰值**：池省不省取决于底座。V=465 档最能说明问题 —— 同一个池对 jemalloc 省 60.1 B/key，对 glibc 反而多占 52.2 B/key（池档位表粒度介于 glibc 的 8 字节对齐与 jemalloc 的跳档之间）。
- **回收**：12 形态在 used 口径下回收率全部 100%。RSS 列不可跨底座比较 —— jemalloc 形态回落至 6–8MB（`arenas.purge` 生效），glibc 形态停在 80–121MB（无 trim，超块走堆不还给 OS），是底座特性而非池的缺陷。
