# Pipeline 性能分析与 Redis 优化技巧总结

## 一、核心结论：你的推理完全正确！

### 1.1 P=1 时为什么 io_uring 更快？

**成本对比：**

```
Redis (epoll) 每请求：~2700ns
  - 4 次系统调用     ~1500ns
  - 内存拷贝         ~200ns
  - 上下文切换       ~1000ns

io_uring (SQPOLL) 每请求：~650ns
  - 1-2 次系统调用   ~500ns
  - 队列管理         ~100ns
  - Buffer ring      ~50ns
  - 零拷贝           0ns

节省: 2050ns ✅
```

**即使 P=1，io_uring 节省的成本 > 固定开销！**

### 1.2 P=5-10 谷底的真正原因

**Redis 的简单批量处理提前发力：**

| 阶段 | Redis 增速 | KVStore 增速 | 谁更快 |

| P=10→P=20 | 1.43x | **1.87x** | KVStore |

## 五、最终总结

### 核心认知

1. ✅ **P=1 时 io_uring 更快**
   - 系统调用更少，零拷贝

2. ✅ **P=5-10 谷底是正常的**
